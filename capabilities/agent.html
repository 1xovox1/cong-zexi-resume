从 Agent 视角：电商企业 AI 运行时架构

在鹏泰宝尊的实践中，我把 Agent 理解为可编排的企业运行时：接入多模型网关、沉淀业务记忆、通过 MCP 与工具安全调用外部世界、用 Planning 把运营意图拆成可执行步骤，并在复杂场景下用多 Agent 分工协作。

能力思维导图 · 电商 Agent 五层架构

① 网关层

  • Dify 统一入口
  • 多模型 API 路由
  • 意图识别分流

② 记忆层

  • RAG 知识库
  • 全局上下文
  • RLHF 反馈迭代

③ 工具层

  • MCP / 自定义节点
  • Python 扩展
  • 多文件批处理

④ 规划层

  • Dify 工作流
  • n8n 编排
  • LangGraph 进阶

⑤ 协作层

  • 垂直业务 Agent
  • 10+ 场景分身
  • 跨部门复用

网关层 —— 多模态 AI 中枢入口

鹏宝 AI 2.0 从单文本助手升级为多模态中枢：海内外大模型 API 统一接入，全局上下文记忆 + 多模态意图路由。

实践：通过 OpenRouter、硅基流动对接全品类模型，按场景做成本与效果平衡。

记忆层 —— RAG + 业务反馈飞轮

知识库覆盖直播合规、跨境政策、产品 FAQ；轻量化 RLHF 机制收集点赞/差评，为知识库与 Prompt 优化提供真实业务信号。

工具层 —— MCP 与 Python 自定义节点

竞品监控系统中，爬虫数据经 n8n 流入 Dify 分析引擎；鹏宝 AI 2.0 支持多文件批量处理、跨境翻译、数据点检等工具链。

规划层 —— Dify / n8n / LangGraph

日报类任务用 Dify 固定工作流；竞品监控用 n8n 定时触发 + 条件分支；复杂多步诊断场景预留 LangGraph 状态图能力。

协作层 —— 10+ 垂直业务 Agent

直播合规话术、业务数据智能点检、跨境多语言翻译、视频脚本生成等各自独立 Agent，共享企业知识库与网关。
